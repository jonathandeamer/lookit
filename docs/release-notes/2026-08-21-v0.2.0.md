# lookit v0.2.0

v0.1.0 fingered an address and printed what came back. v0.2.0 is a browser: it opens on a startpage of finger communities and services with your own bookmarks above them, turns a host's user list into something you can move around in, finds the links inside a response and follows them, and remembers where you've been so you can walk back without re-fetching. 187 commits, and the first release Homebrew installs as a prebuilt binary rather than building from source.

## Install

```
brew install --cask jonathandeamer/tap/lookit
```

On Linux, take a `.deb`, `.rpm`, or archive from the assets below — no Go needed, which is the point on a tilde or pubnix box where the system Go is too old to build from source. `man lookit` works from the cask and from the packages; from an archive, the page is at `man/lookit.1`.

If you installed lookit from this tap before, it was a formula that built from source. That formula is gone; run `brew uninstall lookit` before installing the cask.

## Highlights

### A startpage instead of an empty screen

Run `lookit` with no target and it opens on a built-in catalog of finger communities and services, with your own bookmarks pinned above it. `↓` moves into the list, `↵` goes to whatever's highlighted, `i` returns to the target input, and `h` comes back to the startpage from anywhere. `/` filters on both the address and its description, so `/weather` finds a service you'd otherwise have to remember the address of.

The catalog is a starting point, not a fixed list. If a community or service you use is missing, that's worth an issue.

### Bookmarks you can edit

`b` bookmarks whatever you're looking at, wherever you are. On a user list it bookmarks the host, so drill into a person first if it's the person you want to keep.

Your bookmarks are a plain text file at `~/.config/lookit/bookmarks` (or `$XDG_CONFIG_HOME/lookit/bookmarks`), one target per line, and it explains its own format in a header comment. lookit keeps your comments and ordering, records when you last visited each row, and floats whatever you've been neglecting to the top. It rereads the file whenever you return to the startpage, so you can edit it while lookit is running. `catalog off` on its own line hides the built-in catalog; `sort manual` keeps your file's order.

### Browsing a response

When a response looks like a user list, lookit makes it selectable — arrows to move, `/` to filter, `↵` to finger whoever's highlighted. `Esc` walks back through where you've been, without sending another query. `r` refreshes the current response or retries a failed one, and `Esc` cancels a request while it's still loading.

`L` opens the links lookit found in the response you're reading, and `tab`/`shift+tab` step through them in the reader itself. `↵` opens a link that's clearly a finger target, `f` fingers one that could be read either way, and `y` copies a web URL to your clipboard. Targets lifted from a response are pinned to port 79, so a server can't steer you at some other service.

### Word wrap, when you want it

Responses keep the server's original line layout by default, because that layout is often deliberate. In the reader, `w` word-wraps long prose for the current response and `w` again restores the original. It never splits a token, and the setting is per response rather than global.

### Crossed Fingers

[crossed-fingers.andros.dev](https://crossed-fingers.andros.dev), @tanrax's finger search engine, is in the catalog along with two of its queries, and its result pages are navigable: the results are a selectable list, and you can drill into one and come back out. Search results are the closest thing finger has to discovery, and lookit now treats them as a place you browse.

### Help that fits

`?` shows the keys available on the current screen, derived from the live keymap rather than a hand-kept list. It lays out in one to three columns depending on the width available, and while it's open you can press any key it shows to run that command.

### Under the response

The renderer highlights the standard finger fields, and one-relay forwarding (`user@host@relay`) works. Target parsing is strict about what it accepts, and an outbound query can't smuggle extra RFC 1288 query lines. Response bodies are sanitized once, at the network boundary, before anything reaches your terminal.

## Known issues

- `g` and `G` don't jump to the top or bottom of a response. Arrows, page keys, and `j`/`k` all scroll normally ([#130](https://github.com/jonathandeamer/lookit/issues/130)).
- A user list filters on the login only, so filtering by someone's real name finds nothing even when that name is shown beside it ([#117](https://github.com/jonathandeamer/lookit/issues/117)).
- Viewing the source of a response silently reverts to the rendered body if you resize the terminal ([#153](https://github.com/jonathandeamer/lookit/issues/153)).

## Known limits

- Read-only. lookit fingers servers; it doesn't host a `.plan` or answer queries.
- Finger only. No gopher, gemini, or web.
- The TUI needs a real terminal (TTY).
- Windows isn't published. It compiles, but error classification is Unix-specific, so it isn't shipped.

## Builds

macOS and Linux, amd64 and arm64, plus a `linux/armv6` archive for the Pi Zero and Pi 1. `.deb` and `.rpm` packages for each Linux target. Each archive bundles the binary, `README.md`, `LICENSE`, `man/lookit.1`, and `THIRD_PARTY_NOTICES.md`. Build provenance is attested — `gh attestation verify <file> --repo jonathandeamer/lookit`.
